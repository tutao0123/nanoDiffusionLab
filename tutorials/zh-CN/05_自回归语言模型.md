# 05｜自回归语言模型

自回归语言模型把一段序列分解为一连串“根据左侧预测下一个词元”的任务。这一章对应
`train.py` 中 AR objective 和 `model.py` 中的 `generate`。

## 训练标签如何构造

假设干净序列是：

```text
[Once] [upon] [a] [time]
```

输入和标签分别为：

```text
输入： [Once] [upon] [a]
标签： [upon] [a]    [time]
```

代码就是：

```python
inputs, targets = clean[:, :-1], clean[:, 1:]
logits = model(inputs)
loss = cross_entropy(logits, targets)
```

如果干净 batch 为 `[B, T]`，输入、标签和时间维 logits 分别为 `[B, T-1]`、`[B, T-1]` 和
`[B, T-1, V]`。交叉熵会把前两个维度展平，相当于同时统计所有序列的所有位置。

## 为什么必须使用因果注意力

训练时标签 `targets[:, i]` 就在原序列的右侧。如果位置 `i` 能在注意力中看到未来，它可以直接
读取答案，训练 loss 会虚假地下降。因果 mask 保证位置 `i` 只能访问 `0..i`。

这使训练能够并行：虽然生成必须逐词元进行，但训练时所有位置的下一个词元预测可以在一次
forward 中同时计算。

## AR 验证指标

验证时仓库累计的是所有 target 的 loss sum、正确数和数量，再在进程间求和。最终提供：

- `val_loss`：平均 next-token cross-entropy；
- `val_perplexity = exp(val_loss)`；
- `val_bits_per_token = val_loss / log(2)`；
- `val_token_accuracy`：argmax 恰好命中标签的比例。

perplexity 可以粗略理解为模型对下一个词元的不确定程度，但它依赖 tokenizer 和数据，不能跨
任意数据集直接比较。更不能把它与当前 MDLM 去噪 loss 当作同一个指标。

## 生成过程

给定 prompt，AR 重复下面的步骤：

1. 运行模型，取最后一个位置的 logits；
2. 除以 temperature；
3. 可选地只保留概率最高的 top-k 个词元；
4. softmax 后采样一个词元；
5. 把新词元追加到序列末尾。

温度越低，分布越尖锐，输出通常更稳定；温度越高，低概率词元更容易出现。`top_k=1` 等价于
贪心选择，适合性能测试，但不等同于用于质量比较的 `temperature=1.0, top_k=40`。

## 没有 KV cache 时发生什么

如果 prompt 长度为 32，要生成 128 个词元，uncached 实现会依次处理长度 32、33、34……159
的完整上下文。越靠后，重复计算的历史越多。

## 有 KV cache 时发生什么

缓存实现先对 prompt 做一次 prefill，保存每层的 key/value。之后每一步只输入新生成的一个
词元，并把它的 key/value 追加到缓存：

```text
prefill: 32 tokens → logits + 12 层 KV cache
step 1:   1 token  + cache → next logits + updated cache
step 2:   1 token  + cache → next logits + updated cache
...
```

缓存不含学习参数，因此旧检查点仍兼容。它只改变推理计算方式，不改变模型权重。

当前实现为简单易读使用 `torch.cat` 扩展 cache，而不是预分配固定缓冲区。对于本项目的上下文
长度足够清楚可靠；进一步优化时可以考虑预分配，但应先保留数值一致性测试。

## 验证缓存与非缓存生成一致

```bash
python -m pytest tests/test_sampling.py -q
```

测试会比较：

- cache 得到的最后位置 logits 与完整因果 forward 是否一致；
- cached 和 uncached 的贪心生成是否逐词元相同；
- 超过 block size 时是否明确报错。

随机采样时，每条序列可以拥有自己的 `torch.Generator`。这样 batch size 或多卡分片变化不会
改变某个 prompt 的随机流，是正式公平评测的重要基础。

## 与 MDLM 比较时要固定什么

至少固定：

- prompt token ids；
- 输出词元长度；
- temperature 与 top-k；
- 每个样本的随机种子；
- 推理精度；
- 使用的 checkpoint 与训练 seed。

AR 的网络更新次数等于输出词元数。生成 128 tokens 就是 128 次后续网络更新；MDLM 则可以用
8、16、32 或 64 次全序列更新。延迟比较必须同时报告这个差异。

## 完成检查

- 你能写出一段序列的 AR 输入与右移标签；
- 你能解释训练可并行、生成仍串行的原因；
- `tests/test_sampling.py` 通过；
- 你知道 KV cache 不改变 checkpoint，只减少重复推理计算。
