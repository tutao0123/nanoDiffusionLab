# 06｜掩码扩散语言模型

当前 MDLM 是离散的 masked diffusion 基线。训练时随机破坏干净词元，模型利用双向上下文恢复
被遮住的位置；生成时从大量 mask 开始，多轮并行揭示词元。

## 训练时如何加噪

对 batch 中每条序列采样一个噪声等级 `t`，取值在 0 到 1 之间。然后每个位置独立地以概率 `t`
替换为 mask token：

```text
干净： Once upon a time there was a fox
t=0.5
带噪： Once [M]  a [M]  there [M] a [M]
```

代码中的核心张量为：

- `clean: [B, T]`：干净词元；
- `mask: [B, T]`：布尔值，表示哪些位置被替换；
- `noisy: [B, T]`：送入模型的带噪序列；
- `t: [B]`：每条序列的噪声等级。

若一次随机采样碰巧没有 mask，代码会强制随机选择至少一个位置。否则这一条样本没有任何监督
target，交叉熵无法正常计算。

## 亲自观察 corruption

```bash
python - <<'PY'
import torch
from diffusion import corrupt_tokens

clean = torch.tensor([
    [1, 2, 3, 4, 5, 6, 7, 8],
    [8, 7, 6, 5, 4, 3, 2, 1],
])
noisy, mask, t = corrupt_tokens(
    clean,
    mask_token_id=9,
    t=torch.tensor([0.25, 0.75]),
    generator=torch.Generator().manual_seed(42),
)
print("clean:\n", clean)
print("noisy:\n", noisy)
print("mask:\n", mask)
print("t:", t)
print("targets:", clean[mask])
PY
```

第一条序列通常只有少量 mask，第二条更多。`clean[mask]` 被展平成 `[M]`，其顺序与
`model(noisy, t, mask)` 输出的 `[M, V]` 一一对应。

## 为什么使用双向注意力

被 mask 的位置需要同时利用左侧和右侧线索：

```text
The little [MASK] ran home.
```

右侧的 `ran home` 可能帮助判断缺失位置。MDLM 将 `is_causal=False`，所以所有可见位置可以
彼此注意。mask token 本身只是“未知”的占位符，不代表删除这个位置。

## 时间条件的作用

相同的局部模式在 10% mask 和 90% mask 下置信度应当不同。`time_mlp` 把 `t` 投影到隐藏维度，
加到每个位置的表示中，让模型知道当前噪声强度。

如果调用 forward 时没有显式传入 `t`，模型可以根据输入中 mask 的实际比例推断；训练代码会
显式传入采样到的 `t`。

## loss 只计算被 mask 的位置

```python
logits = model(noisy, t, mask)  # [M, V]
targets = clean[mask]           # [M]
loss = cross_entropy(logits, targets)
```

可见位置不作为 target，因为模型已经在输入中看到它们。先选择 masked hidden states，再做
`lm_head` 投影，也避免创建完整 `[B, T, V]` logits。

验证时使用固定的 0.10、0.25、0.50、0.75、0.90 mask ratios，分别报告 loss 和 accuracy，再
计算平均值。固定 ratios 比每次随机 t 更容易比较 checkpoint，但它仍然是去噪指标，不是 AR
perplexity。

## 从 mask 到完整序列

采样器 `sample_masked` 从带 prompt 的全 mask 序列开始。每一轮：

1. 找到仍为 mask 的位置；
2. 根据剩余 mask 比例得到当前 `t`；
3. 只为 mask 位置计算 logits；
4. 对每个 mask 位置采样候选词元；
5. 读取候选词元的概率作为 confidence；
6. 在每条序列中揭示一批置信度最高的位置；
7. 保留其他位置为 mask，进入下一轮。

若当前有 `N` 个 mask、还剩 `S` 轮，代码揭示 `ceil(N / S)` 个位置。这样最后一轮一定能够清空
所有 mask。

```text
step 0: Once upon [M] [M] [M] [M] [M] [M]
step 1: Once upon [M] time [M] [M] a [M]
step 2: Once upon a time [M] was a [M]
step 3: Once upon a time there was a fox
```

高置信度位置不一定从左到右出现，这正是并行去掩码与 AR 解码最直观的区别。

## 为什么 prompt 不会被改写

`sample.py` 先创建全 mask 的 `initial`，再把 prompt tokens 放到开头。采样器每轮只对
`x == mask_token_id` 的位置赋值，因此已有 prompt 不会进入候选集合。

## 步数的质量–速度权衡

更少步数意味着每轮必须一次确定更多位置，错误缺少后续上下文修正；更多步数让模型先确定容易
的位置，再利用它们帮助难位置，但延迟近似随网络更新次数增加。

正式结果中，8 步 MDLM 的 batch-1 延迟约 0.045 秒，64 步约 0.348 秒；质量也随步数提高，
但 64 步仍明显落后于 AR。这说明并行能力真实存在，同时当前训练和采样基线仍有较大改进空间。

## 当前采样器没有做什么

为了保持基线紧凑，当前没有加入重掩码、token correction、classifier-free guidance、精确 MDLM
likelihood weighting 或块扩散。理解这一边界很重要：报告描述的是当前可读实现，而不是所有
扩散语言模型方法的上限。

## 完成检查

- corruption 脚本能够打印不同 mask ratio 的两条序列；
- 你能解释为何 loss 只使用 `clean[mask]`；
- 你知道 MDLM 使用双向注意力和时间条件；
- 你能描述一轮 confidence-based reveal 做了什么；
- 你不会把 MDLM 去噪 loss 直接称为 perplexity。
