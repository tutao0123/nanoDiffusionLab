# 09｜训练一亿参数模型

这一章解释正式 TinyStories 配置、词元预算、单卡与四卡命令，以及运行后应当检查哪些产物。
完整复现需要数小时级 GPU 时间；先读懂预算再启动，不要把 smoke test 命令误当作正式实验。

## 读取配置而不是猜配置

```bash
sed -n '1,240p' configs/tinystories_106m.py
```

核心模型为 12 层、9 头、隐藏维度 576、上下文 1,024。训练配置包括：

- 每卡 batch size 32；
- 梯度累积 2 次；
- 最多 20 亿输入 tokens；
- 5 亿、10 亿和 20 亿 token 里程碑 checkpoint；
- BF16；
- gradient checkpointing；
- AdamW 与 cosine learning-rate decay；
- 默认关闭 `torch.compile`，避免动态 masked cardinality 带来的不稳定编译行为。

## 先确认参数量

```bash
python - <<'PY'
from config import ModelConfig
from model import Transformer

common = dict(vocab_size=50257, block_size=1024, n_layer=12, n_head=9, n_embd=576)
ar = Transformer(ModelConfig(
    **common, objective="autoregressive", mask_token_id=None, time_conditioning=False
))
mdlm = Transformer(ModelConfig(
    **common, objective="masked_diffusion", mask_token_id=50257, time_conditioning=True
))
print("AR:", f"{ar.parameter_count():,}")
print("MDLM:", f"{mdlm.parameter_count():,}")
PY
```

预期为：

```text
AR: 106,276,032
MDLM: 106,610,112
```

## 计算每个 optimizer step 的输入词元

公式：

```text
tokens_per_step = batch_size × block_size × gradient_accumulation × world_size
```

参考四卡配置：

```text
32 × 1,024 × 2 × 4 = 262,144 tokens/step
```

达到至少 20 亿 tokens 需要：

```text
ceil(2,000,000,000 / 262,144) = 7,630 steps
```

最后一个完整 step 会略微超过预算，因此报告为 2,000,158,720 输入 tokens。这种按完整 batch
越过阈值的行为是确定的，并在两种目标中保持一致。

## 四卡启动单个目标

先确认四张卡为空闲：

```bash
nvidia-smi
```

AR：

```bash
python -m torch.distributed.run --standalone --nproc_per_node=4 train.py \
  --config configs/tinystories_106m.py \
  --objective autoregressive \
  --out-dir out/tutorial-tinystories-106m-ar
```

MDLM：

```bash
python -m torch.distributed.run --standalone --nproc_per_node=4 train.py \
  --config configs/tinystories_106m.py \
  --objective masked_diffusion \
  --out-dir out/tutorial-tinystories-106m-mdlm
```

不要同时在同四张卡上启动两条命令。参考流程先完成 AR，再完成 MDLM，避免争抢显存和让吞吐
测量失去可比性。

## 使用成对运行脚本

完整顺序执行并自动恢复已有 checkpoint：

```bash
bash scripts/run_tinystories_pair.sh
```

它会依次：

1. 检查 manifest；
2. 使用 4 个 DDP 进程训练 AR；
3. 生成固定 seed 样本；
4. 使用相同配置训练 MDLM；
5. 生成固定 seed 样本；
6. 调用 `scripts/compare_runs.py` 生成成对报告。

如果你的 GPU 数不是 4，应当先手动运行，而不是直接使用这个固定四卡脚本。

## 单卡如何保持相同全局 batch

直接把 `world_size` 从 4 改为 1，而仍使用梯度累积 2，每 step 只处理 65,536 tokens，并且
`max_iters=10,000` 会先于 20 亿预算停止。那不是相同 token-budget 实验。

可以把梯度累积改为 8：

```bash
CUDA_VISIBLE_DEVICES=0 python train.py \
  --config configs/tinystories_106m.py \
  --objective autoregressive \
  --out-dir out/tutorial-tinystories-106m-ar-single \
  --gradient-accumulation-steps 8
```

此时 `32 × 1,024 × 8 × 1` 仍为 262,144 tokens/step。梯度累积不会让 8 个 micro-batch 同时留在
显存，因此主要代价是更长时间，而不是八倍 activation memory。

如果显存不足再降低 `batch_size`，并相应提高梯度累积保持全局 batch。例如 batch 8、累积 32：

```text
8 × 1,024 × 32 × 1 = 262,144
```

## 启动前做一个 10 step GPU 检查

```bash
python -m torch.distributed.run --standalone --nproc_per_node=4 train.py \
  --config configs/tinystories_106m.py \
  --objective masked_diffusion \
  --out-dir out/tutorial-tinystories-106m-mdlm-smoke \
  --max-iters 10 \
  --eval-interval 5 \
  --eval-iters 2
```

这个命令会真实构建一亿参数模型并经过 DDP、BF16、gradient checkpointing、评估和保存，适合
发现 OOM 或 NCCL 问题。它不用于生成质量判断。

## 如何读训练第一行

rank 0 会打印类似：

```text
masked_diffusion | 106.61M params | device=cuda:0 | world_size=4 |
tokens/step=262,144 | planned_steps=7,630
```

在正式启动前检查：

- objective 是否正确；
- 参数量是否约 106M；
- world size 是否为 4；
- tokens/step 是否为 262,144；
- planned steps 是否为 7,630。

任何一项与实验计划不符，都应先停止并检查命令，而不是训练几小时后再解释。

## 训练过程中看哪些指标

`metrics.jsonl` 的 train 事件包含：

- `loss`；
- `learning_rate`；
- `grad_norm`；
- `tokens_seen` 与 `target_tokens_seen`；
- `tokens_per_second`；
- `peak_memory_mb`；
- AR 的 `token_accuracy`，或 MDLM 的 `masked_accuracy` 与 `mask_ratio`。

eval 事件包含目标专属验证指标。单步抖动很正常，应观察几百 step 的趋势和两个 seed 的复现性。

## 参考完成结果

两组 seed 均训练 20 亿输入 tokens。参考平均训练吞吐：

| 目标 | seed 1337 | seed 2027 |
|---|---:|---:|
| AR | 242.9K tok/s | 244.8K tok/s |
| MDLM | 287.1K tok/s | 289.4K tok/s |

这些数字只适用于参考 4×A40 PHB 服务器。你的结果更慢不等于代码错误，应先比较 GPU、拓扑、
PyTorch、batch、精度和评估频率。

## 完成检查

- 参数量脚本得到 106,276,032 和 106,610,112；
- 你能独立计算当前命令的 tokens per optimizer step；
- 四卡 smoke test 的 world size、计划 step 和 objective 正确；
- 你知道单卡直接运行默认配置不会自动得到同样的 20 亿 token 实验；
- 正式运行目录持续写入 metrics 和 checkpoint。
