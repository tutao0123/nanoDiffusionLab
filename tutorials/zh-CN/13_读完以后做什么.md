# 13｜读完以后做什么

走到这里，你已经拥有一条从字符 smoke test 到一亿参数 DDP 与正式盲评的完整基线。下一步最
有价值的工作不是无目的增加代码，而是选择一个明确问题，在保持评测协议可比较的前提下修改。

## 方向一：改进当前 MDLM

正式结果显示 MDLM 有速度优势，但重复和连贯性明显落后。可以依次研究：

- 非均匀或 likelihood-aware 的噪声与 loss weighting；
- 不同 reveal schedule；
- 低置信度 token 的重掩码与修正；
- 训练噪声分布与采样轨迹是否匹配；
- end-of-text 与长度建模；
- 采样 temperature、top-k 与 step count 的系统敏感性。

一次只改变一个主要因素，并继续使用相同 checkpoint seed 数、1,000 prompts 与盲评流程。否则
质量变化无法归因。

## 方向二：实现 Block Diffusion

Block Diffusion 的目标是在块内并行、块间保持某种顺序结构，尝试平衡 AR coherence 与 MDLM
parallelism。实现前应明确：

1. attention mask 如何定义；
2. 训练时哪些块可见、哪些位置作为 target；
3. 生成时 block size、block order 和块内 step；
4. cache 哪些状态可以复用；
5. 与 AR/MDLM 比较时网络更新次数如何统计。

不要只新增 objective 名称而继续使用完全双向 attention。Block Diffusion 的关键就是可见性与
解码日程。

## 方向三：扩大规模

可以测试 350M、1B 或更大模型，但规模扩展应同时回答：

- 两种目标参数量是否仍接近；
- 使用相同 input tokens、FLOPs 还是 wall-clock budget；
- DDP 是否仍适合，何时才需要 FSDP/ZeRO；
- 更大模型是否改变质量–速度前沿；
- 至少三个随机 seed 是否一致。

仓库中的 `configs/fineweb_350m.py` 是目标配置，不代表已有生产级 FineWeb 数据管线。公开结果前
应补齐数据 revision、tokenizer、去重与分片记录。

## 方向四：把实验变成可复现贡献

一个可比较的 pull request 至少应包含：

- 清楚的问题与假设；
- 新配置或命令；
- 数据和 tokenizer 版本；
- 代码 commit；
- GPU、拓扑、PyTorch、CUDA、精度和 world size；
- 参数量、上下文、输入 tokens 和监督 targets；
- 至少两个 seed，重要结论建议三个；
- 训练曲线、生成样本与质量–延迟评测；
- 失败或负面结果，而不是只保留最好一次。

## 如何整理成社交平台教程

不建议把整个仓库 README 原样复制成一篇超长文章。可以拆成连续内容，每篇只回答一个问题：

1. **为什么语言模型不一定只能从左到右生成？** 使用 decoding GIF 建立直觉。
2. **同一个 Transformer 如何训练 AR 和 MDLM？** 展示 attention 与 loss 的最小差异。
3. **十分钟跑通字符扩散语言模型。** 使用第 07 章命令与字符动画。
4. **四张没有 NVLink 的 A40 如何训练 106M 模型？** 解释 DDP 与 token budget。
5. **10,000 个样本的真实结果。** 展示质量–延迟前沿，不回避 MDLM 质量落后。
6. **下一步如何改进？** 把失败模式转化为研究问题。

每篇开头先给结论或动态图片，中间给关键原理和最短可运行命令，末尾链接到本教程对应章节与
完整报告。社交平台内容负责吸引和解释，仓库负责精确命令、版本与证据。

## 教程维护原则

当命令行参数、目录或默认配置变化时，应同时更新：

- README 中的最短入口；
- 本教程的相关章节；
- 测试与 shell syntax check；
- 已完成报告中的复现说明，但不要改写历史测量值。

教程中的预期输出应强调结构和数量，不强迫读者得到完全相同的吞吐。硬件相关数字必须标为参考
平台结果。

## 最终完成检查

- 你能从空环境跑通字符 AR 与 MDLM；
- 你能解释共享 Transformer 中目标专属的最小差异；
- 你能正确计算单卡和多卡 tokens per step；
- 你能恢复 DDP checkpoint 并识别 world-size 限制；
- 你能复现或阅读生成质量–速度报告；
- 你知道下一次修改要回答的具体研究问题。
