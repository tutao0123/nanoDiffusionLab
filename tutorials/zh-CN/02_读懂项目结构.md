# 02｜读懂项目结构

这一章不逐行解释代码，而是建立阅读顺序。nanoDiffusionLab 刻意保留少量顶层文件，让核心
算法可以直接打开查看；数据准备、正式评测、绘图与报告等工作流统一放在 `scripts/`。

## 顶层结构

```text
nanoDiffusionLab/
├── config.py              模型与训练配置
├── data.py                字符数据和词元分片读取
├── model.py               共享 Transformer、注意力与 AR 生成
├── diffusion.py           掩码破坏、MDLM loss 与并行采样
├── experiment.py          日志、原子保存、环境与源码快照
├── evaluation.py          提示抽样、本地指标与盲评统计
├── train.py               单卡和 DDP 共用的训练入口
├── sample.py              AR/MDLM 共用的采样入口
├── configs/               可以直接运行的 Python 配置
├── scripts/               数据准备、成对训练、评测、报告和绘图
├── tests/                 行为测试
├── tutorials/             当前这套逐步教程
├── docs/                  架构说明与图片
└── reports/               已完成实验的报告与精简统计
```

顶层 Python 文件的数量不是越少越好。如果把模型、数据和训练全部隐藏进多层 package，新人只会
看到简洁的入口，却更难追踪一个 batch 如何进入模型。当前结构把“研究核心”留在顶层，把一次性
工作流放到 `scripts/`，是有意的取舍。

## 两个程序入口

训练从 `train.py` 开始：

```bash
python train.py --help
```

采样从 `sample.py` 开始：

```bash
python sample.py --help
```

这两个入口都通过命令行参数选择配置和检查点，但真正的模型定义只有一份 `Transformer`。

## 建议阅读顺序

### 第一遍：只建立主流程

按下面的顺序搜索函数名，不必理解每一行：

1. `config.py` 中的 `ModelConfig` 与 `TrainConfig`；
2. `train.py` 中的 `main`；
3. `data.py` 中的 `CharacterData.batch`；
4. `model.py` 中的 `Transformer.forward`；
5. `train.py` 中的 `objective_loss`；
6. `diffusion.py` 中的 `masked_diffusion_loss`；
7. `sample.py` 中的 `main`。

你会看到一条完整链路：

```text
配置 → 数据 batch → Transformer → 目标专属 loss → backward
                                      ↓
检查点 → sample.py → AR generate 或 MDLM sample_masked
```

### 第二遍：比较两种目标

重点看四个分支：

- `ModelConfig.causal` 决定注意力是否因果；
- `objective_loss` 决定右移标签还是随机掩码；
- `Transformer.time_mlp` 只在 MDLM 中启用；
- `sample.py` 根据检查点中的 `objective` 选择生成器。

### 第三遍：研究工程可靠性

阅读 `experiment.py` 和训练主循环中的检查点逻辑。这里记录的不只是模型权重，还包括优化器、
梯度缩放器、训练 step、已处理词元、每个 rank 的随机数状态和 world size。精确恢复依赖这些
状态，而不是简单地重新加载 `model.state_dict()`。

## 配置为什么使用 Python 文件

例如 `configs/shakespeare_char.py` 最终定义一个 `TrainConfig`：

```python
config = TrainConfig(
    model=ModelConfig(...),
    data_path="data/tinyshakespeare/input.txt",
    out_dir="out/shakespeare-mdlm",
    ...
)
```

`config.py` 使用 `runpy.run_path` 加载它。这样配置仍有类型明确的 dataclass，也可以使用数字
分隔符、表达式和注释。命令行只覆盖经常变化的字段，例如 objective、输出目录、seed、批量和
训练预算；模型尺寸等结构性参数留在配置文件中。

## 核心层与工作流层

可以用下面的边界判断一个新文件应放在哪里：

- 被训练或采样主路径直接复用的算法与状态工具，属于顶层核心层；
- 下载数据、组合多次训练、绘图、生成报告或调用外部 API，属于 `scripts/` 工作流层；
- 实验产物进入 `out/`，可分享的精简结论进入 `reports/`；
- 原理说明进入 `docs/`，面向新人的连续学习内容进入 `tutorials/`。

这也是为什么成对训练报告生成器位于 `scripts/compare_runs.py`，而通用的评测指标仍保留在
`evaluation.py`。

## 用搜索代替滚动阅读

推荐使用 ripgrep：

```bash
rg -n "def objective_loss|def masked_diffusion_loss|def generate|def sample_masked" .
rg -n "objective ==" train.py sample.py
rg -n "save_checkpoint|resume" train.py
```

研究代码通常不是从第一行顺序读到最后一行。先找到入口与分支，再沿函数调用深入，更容易保持
完整的心智模型。

## 完成检查

- 你能指出训练入口、采样入口、共享模型和 MDLM 专属逻辑分别在哪个文件；
- 你知道 `scripts/` 存放工作流，而不是另一套核心模型；
- 你能描述一次训练从配置到 batch、loss 和检查点的基本路径。
